The question

When we transfer a customer
from Tobi to a human agent…

…do they land on the team that matches their reason for calling?

If they do → routing works. If they don't → we're paying a cost every time (customer waits, agent transfers again, satisfaction drops, cost per contact goes up).

How we measured it — credibility

Four steps. Every number is traceable to a specific SQL query.

1

Tobi intent

Extract customer intent for each Tobi conversation (last valid intent log)

2

Transfer flag

Was the session transferred to an agent? (Diogo's Corrected_Handover, chosen by data)

3

ACD intent

What did the ACD system say the customer wanted? (first PX at agent pickup)

4

Compare

Same intent → routed correctly. Different intent → misrouted.

Not an opinion

Two systems classify the same customer. We're just checking whether they agree.

Confidential — InternalSlide 7 / 13
What this actually is

A taxonomy mismatch
— not a routing bug.

Both systems classify customer intent. For a specific set of intent families they use different labels for the same customer. The routing may still deliver the customer to the right team — but our KPI compares the labels, and the labels disagree.

Old framing

"Fix the routing."
→ Rebuild the routing model.

→
New framing

"Reconcile the taxonomies."
→ Fix 8 specific intent families.

Orders of magnitude smaller in scope. This is the positive story.

What we recommend — three actions

 

  1. Prioritise taxonomy reconciliation on 8 intent families.
    PX25, PX8, PX9, PX86, PX71, PX50, PX43, PX12. Own-team meeting with Tobi and ACD leads. For each family, confirm what it represents on each side, and either align labels or add a translation layer.
  2. Build a live monitoring dashboard.
    Once taxonomies are aligned, we need to watch the KPI move. Full spec ready — 8 panels, refresh daily, drill down by intent / queue / time / segment.
  3. Repeat the analysis quarterly.
    Same SQL pipeline on updated (non-sampled) sources. Confirms the fix landed and catches regressions.

Caveats — we disclose them up front

 

  • Sample data. Analysis runs on a fixed 12-month window (17-Jul-2025 → 20-Jul-2026). When productionised on non-sampled sources the SQL translates 1-for-1.
  • The final measurable universe is 310K sessions — ~2% of the full 16.1M Tobi sessions. Coverage funnel disclosed in the analysis repo.
  • PX103 is a large ACD destination absorbing traffic from many Tobi families. Awaiting confirmation from the ACD team on whether it is a legitimate product family or a catch-all bucket. The 76% may be adjusted for a "PX103 unclassified" split in a follow-up cut.

Every claim in this deck is traceable to a specific SQL query in the analysis repository. Nothing is hidden.
