How to read this deck — plain-English definitions

Three things repeat throughout. Here is what they mean.

KPI universe = 310,146 sessions

The only sessions where we can fairly compare Tobi and ACD: (a) Tobi captured a customer intent, (b) the session was transferred to a human agent, and (c) ACD tagged the interaction with its own intent.

Everything smaller than the 16.1M total drops out because one of the two sides did not classify the customer — nothing to compare against.

Tobi intent family = "PX + number"

Both Tobi (the chatbot) and ACD (the call-routing system) tag every conversation with an intent code of the form PX8, PX25, PX103, etc. This is Vodafone Portugal's internal taxonomy — one PX code per topic area (e.g. billing, contract, technical, etc.).

Both systems use the same PX naming scheme. Misrouting = when Tobi says PX9 but ACD's queue is labelled PX83 for the same customer.

Human-readable label per PX code lives with the ACD team (Diogo). We report the codes as they appear in the raw data.

Colour legend used in every chart

Red = high misroute rate (bad) Pink = moderately high (concerning) Green = well-routed (good) Grey = neutral / comparison baseline Dashed line = overall 75.9% average (for reference)

Misroute rate = share of transferred sessions where labels disagree

Formula = (misrouted sessions ÷ KPI universe) × 100. A session is "misrouted" when Tobi's PX code ≠ ACD's PX code. Volume tags on the charts (in brackets) are the number of sessions inside that slice — not percentages.

Every channel misroutes at least 3 in 4 sessions.

The insight

App is the best-performing channel at 73%, Web at 78%, and the partner channels (amigo_web, amigo_app) sit between 75% and 83%. Even the best channel is misrouting three in four sessions — reinforcing that the problem is intent-classification, not channel-specific.

Confidential — InternalSlide 10 / 15
What this actually is

A taxonomy mismatch
— not a routing bug.

Both systems classify customer intent. For a specific set of intent families they use different labels for the same customer. The routing may still deliver the customer to the right team — but our KPI compares the labels, and the labels disagree.

Old framing

"Fix the routing."
→ Rebuild the routing model.

→
New framing

"Reconcile the taxonomies."
→ Fix 8 specific intent families.

Orders of magnitude smaller in scope. This is the positive story.

  1. Prioritise taxonomy reconciliation on 8 intent families.
    PX25, PX8, PX9, PX86, PX71, PX50, PX43, PX12. Own-team meeting with Tobi and ACD leads. For each family, confirm what it represents on each side, and either align labels or add a translation layer.
  2. Build a live monitoring dashboard.
    Once taxonomies are aligned, we need to watch the KPI move. Full spec ready — 8 panels, refresh daily, drill down by intent / queue / time / segment / channel.

    Same SQL pipeline on updated (non-sampled) sources. Confirms the fix landed and catches regressions.

Caveats — we disclose them up front

 

  • Sample data. Analysis runs on a fixed 12-month window (17-Jul-2025 → 20-Jul-2026). When productionised on non-sampled sources the SQL translates 1-for-1.
  • The final measurable universe is 310K sessions — ~2% of the full 16.1M Tobi sessions. Coverage funnel disclosed in Slide 5.
  • PX103 is a large ACD destination absorbing traffic from many Tobi families. Awaiting confirmation from the ACD team on whether it is a legitimate product family or a catch-all bucket.
  • PX code → human label mapping is owned by the ACD team. We report codes verbatim; Diogo to supply business names for the 8 families flagged on Slide 7.

Every claim in this deck is traceable to a specific SQL query in the analysis repository.
